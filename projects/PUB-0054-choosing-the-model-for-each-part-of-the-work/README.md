# Choosing the Model for Each Part of the Work

## LinkedIn Summary

I'm having to pay more attention to which AI model I use for each part of a project.

Astra is helping me get a lot more done, but intensive projects are also burning through my available credits much faster than I expected.

I'm starting to separate the work. Use Astra for the parts that need more thought, then hand the routine steps to a lighter model once the decisions and instructions are clear.

Even within one project, I don't necessarily need the same model doing everything. The handoff matters, though. If I have to explain the whole project again every time I switch, that's more work for me.

I'm still figuring out that balance. I'm getting more done, and I'm also running through my allowance a lot faster.

## Overview

Using AI on intensive projects has created a practical problem for me. I can work through more tasks, but I can also use up my available credits quickly.

That has me thinking about model routing: choosing the model for the particular task, and sometimes changing models as the work moves from deciding what to do into carrying out an established process.

## Role

I'm deciding which parts of the work need Astra and which parts I can hand to another model. This is a workflow I'm refining, rather than a claim that I have an automatic router making every decision.

## Scope Of Work

The choice can happen within a single project. Working through an unclear problem and following a settled set of instructions are different tasks, even when they contribute to the same result.

I want the model choice to reflect that difference.

## Key Actions

- Identify where the task still needs reasoning, judgment, or clarification.
- Use Astra for the parts where I think that additional capability is warranted.
- Save the decisions, relevant context, and remaining instructions.
- Hand clearly defined work to a lighter model.
- Check the result before treating that part of the work as complete.

## Important Features

The handoff is part of the routing decision. A model needs to know what has already been decided, what it is allowed to do, and what still needs attention.

I've already asked for this separation in my publishing workflow: prepare and review the wording first, then let another model pick up the approved material and follow the release instructions.

## Constraints And Decisions

Switching models does not remove the need for context or verification. If the next model needs me to reconstruct the entire project, the handoff has added work.

I'm also keeping credits and tokens separate in how I describe the problem. My observation is that I'm consuming my available allowance quickly. I have not measured a task-by-task token comparison or a fixed relationship between tokens and credits.

## Deliverables

The intended handoff is a saved record of the decisions, the current work, and the next steps. It should let the next model continue without asking me to repeat the background.

## Outcome

I'm getting more work done while also reaching my usage limits sooner. I'm still working out which tasks benefit from Astra and which can be completed satisfactorily with a lighter model.

## Tools And Methods

Codex, Astra, task-level model selection, saved project context, explicit instructions, and review of the completed work.

## Evidence And Limitations

This is a description of my experience and the workflow I'm developing. It is not a model benchmark, a measured savings claim, or a claim that lighter models are suitable for every routine task.
