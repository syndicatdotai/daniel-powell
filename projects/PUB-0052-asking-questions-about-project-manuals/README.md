# Asking Questions About Project Manuals

## LinkedIn Summary

You can put the owner's manuals, manufacturer spec sheets, and technical documentation for a project into Gemini Notebook, the app previously known as NotebookLM, and ask questions in plain English.

What maintenance does this equipment need? What does the manufacturer say about installation? Where is the procedure for that fault code?

The answer is grounded in the documents you provide, with citations you can open to see the original passage. You can also select the particular manual or group of documents you want it to use.

I'd keep the equipment model and document revision with each source so I'm asking about the right equipment. Then I can check the answer against the actual manufacturer's instructions.

## Overview

A project can have equipment manuals, product specifications, installation instructions, and technical bulletins scattered across separate documents. This workflow puts those references into a notebook so you can ask about their contents in ordinary language.

Google renamed NotebookLM to Gemini Notebook in July 2026. The product remains a standalone research tool. [Google's naming announcement](https://blog.google/innovation-and-ai/products/gemini-notebook/notebooklm-gemini-notebook/)

## Role

I'm describing a way to organize and question project documentation. This is a workflow explanation, with example questions, rather than a report of a completed equipment review.

## Scope Of Work

Gather the manufacturer's documents that apply to the equipment or products on the project. That might include an owner's manual, a maintenance guide, a specification sheet, and installation instructions.

PDFs can be added as sources. Keep enough information with each document to identify the equipment model and the revision being referenced. [Google's source documentation](https://support.google.com/gemininotebook/answer/16215270?hl=en)

## Key Actions

Create a notebook for the project, add the relevant documents, and select the sources that apply to the question.

Questions could include:

- What routine maintenance does this manual call for?
- What needs to be checked before installation?
- Where does the manual explain this fault code?
- Which document supports that answer?

## Important Features

Source citations let you open the supporting passage and read it in context. You can narrow the selected sources when a notebook contains manuals for several pieces of equipment. [Google's chat documentation](https://support.google.com/gemininotebook/answer/16179559?hl=en)

## Constraints And Decisions

The document still needs to match the equipment. An answer from an older manual or a different model may be irrelevant even if it has a citation.

I'd check the original passage, including the surrounding instructions, before using the answer for the work.

## Deliverables

The intended result is a project reference notebook containing the applicable manufacturer documents, along with answers that point back to their supporting material.

## Outcome

This gives you a way to locate and interpret information across the project documents. No project results or time savings have been measured for this example.

## Tools And Methods

Gemini Notebook, manufacturer PDFs, natural language questions, source selection, and review of cited passages.

## Evidence And Limitations

The software capabilities are supported by Google's documentation. The equipment questions are illustrative; no specific equipment manual was tested for this post.

If the supplied material does not contain the answer, more documentation may be needed. [Google's explanation of source coverage](https://support.google.com/gemininotebook/answer/16269187?hl=en)
