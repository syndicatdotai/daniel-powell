# Keeping track of blueprint revisions with AI

## LinkedIn Summary

I've been using AI to document changes I've made to blueprints and architectural drawing sets.

I tell it how we got to the decision, whether that was a meeting, phone call, text, or site visit. Who was involved, what we decided, and what changed in the drawings.

It puts together a revision document that goes with the updated set. Basically a receipt for the changes, something I can print on a sheet of paper or save with the drawings.

For a few changes, it grabs screenshots of the revised drawings. When there are a lot of revisions, it writes them out in a list.

It keeps the drawing references, exported PDF filename, and revision number in sync so the document matches the version of the print it belongs to.

Once I've set up who needs to receive revisions for that project, it emails them too.

## Overview

I use AI to create a revision document after changes have been made to blueprints and architectural drawing sets. It accompanies the updated drawings and records what changed, who was involved in the decision, and how that decision came about.

I think of it as a receipt for the changes. I can print it on a sheet of paper or save it with the revised set.

## Role

I supply the context behind the decisions and describe the changes already made to the drawings. I also set up the appropriate recipients for each project before using the email distribution step.

## Scope Of Work

The workflow documents completed drawing revisions. It combines the decision history, a record of the changes, supporting screenshots where appropriate, and references to the affected prints and exported PDFs.

The decision history can come from a meeting, phone call, text exchange, or site visit.

## Key Actions

After updating the drawings, I provide:

- How the decision was made.
- Who was involved.
- What was decided.
- What changed in the blueprints and architectural set.

The process creates the accompanying revision document from that information. For a few changes, it captures screenshots of the updated drawings. For a larger group of revisions, it writes out the changes in a list.

## Important Features

The document identifies the appropriate print, exported PDF filename, and revision number. Those references stay in sync so the record matches the drawing version it accompanies.

The decision context remains alongside the documented changes. The record includes both what was changed and how the people involved arrived at that decision.

## Constraints And Decisions

This is a retrospective record of changes already made. It is not a list of proposed edits or instructions for future drawing work.

Screenshots are used when the revisions are manageable enough to show that way. Larger groups of changes are documented in writing. No fixed numerical threshold is specified here.

Email distribution requires the appropriate parties to be configured for the project first.

## Deliverables

- A revision document that can be printed or saved with the updated drawings.
- The decision source, participants, decision, and completed drawing changes.
- Supporting screenshots or a written revision list.
- References to the affected print, exported PDF filename, and revision number.
- Email distribution to the configured project recipients.

## Outcome

I have an automated way to create a record that accompanies the revised drawing set. It documents changes that have happened and keeps that account associated with the correct print and saved PDF version.

## Tools And Methods

The process uses AI to organize supplied decision history and completed drawing changes into a revision document. It includes screenshot capture, written revision lists, drawing and PDF references, and configured email distribution.

## Evidence And Limitations

This account describes my current workflow. It does not include private drawings, correspondence, recipient details, or a specific project's revision history. No measured time savings or error rate is claimed.
