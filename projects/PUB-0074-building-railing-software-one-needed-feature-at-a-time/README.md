# Building Railing Software One Needed Feature at a Time

## LinkedIn Summary

I've been developing custom railing software on and off for about ten months. It lets me put shop drawings together relatively quickly, with AutoCAD drawings, a cut sheet, and a printable dimensioned railing sheet as the outputs.

When I run into a feature it doesn't have, I have a decision to make. Do I spend the time building that feature, or just draw what I need in AutoCAD? Sometimes the time involved is roughly the same.

For me, it depends on whether I'll use the feature again. If it applies to other jobs, building it can make sense. If it's something unusual that I may never need again, drawing it directly can be the better use of my time.

That's how the application has developed. I add features when an actual project gives me a reason to build them.

Some of the more complicated projects I've done are still better handled directly in AutoCAD. I make that call based on the work in front of me.

## Overview

I've been developing a custom railing application intermittently for about ten months. Development follows the requirements of actual projects, with features added as the need arises.

## Role

I work on the application and decide when a project requirement warrants a new feature. I also prepare drawings directly in AutoCAD when that is the more practical approach.

## Scope Of Work

The application supports railing shop drawing preparation. Its outputs include drawings usable in AutoCAD, a cut sheet, and a printable sheet showing the railing geometry and dimensions.

## Key Actions

When a project requires something the application cannot yet handle, I compare the effort of implementing that feature with drawing the required detail in AutoCAD.

Sometimes those options take roughly the same amount of time. In that situation, I consider whether the feature would also be useful on future jobs. Repeated use can justify development, while an unusual requirement may be better resolved directly in the drawing.

## Important Features

The application produces drawing and fabrication information that I can use in the existing workflow. AutoCAD remains part of that process, both as a destination for generated drawings and as the tool I use for work better handled directly.

## Constraints And Decisions

I add capabilities when real work calls for them. That has spread development over a series of projects and needs across approximately ten months.

Some more complicated projects have been better handled directly in AutoCAD. Complexity alone does not make a feature worth adding when its future usefulness is limited.

## Deliverables

The software produces AutoCAD drawings, a cut sheet, and a printable dimensioned railing sheet.

## Outcome

I can prepare supported railing shop drawings relatively quickly and decide case by case whether a missing capability belongs in the application.

## Tools And Methods

The workflow combines a custom railing application, incremental feature development, and direct AutoCAD drafting. Feature selection depends on the immediate requirement, development effort, and likely reuse.

## Evidence And Limitations

The development period and comparison of effort come from my own experience. The time required depends on the feature and project. The application supports the workflows I've developed into it, with other projects continuing through direct AutoCAD drafting.
