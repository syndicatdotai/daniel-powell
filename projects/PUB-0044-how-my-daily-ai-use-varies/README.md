# How my daily AI use varies

## LinkedIn Summary

Some days I only use AI for a few minutes. That does not include the automations that run in the background without much input from me.

Sometimes I only need a quick search, a note organized, or a small question answered. Other days I may spend four or five hours using it for research, drafting, document handling, or several Codex tasks across different projects.

#Codex #AI #ConstructionTechnology

## Overview

This record describes how Daniel's direct use of AI changes from one workday to another. Some days involve only a few minutes of direct interaction. Other days may include approximately four or five hours spread across research, drafting, document handling, project records, and several separate Codex tasks.

Routine automations that run with little direct involvement are separate from those durations. The distinction matters because background automation activity does not represent the amount of time Daniel spends actively working with AI.

## Role

Daniel decides when a task needs AI support, supplies the working context, moves between the relevant records or conversations, and reviews the results before using them.

For short interactions, the task may be a quick search, organizing a note, or answering a bounded question. Longer sessions can involve several different kinds of work and may move across separate project contexts.

## Scope Of Work

Direct AI use may include:

- researching a construction, administrative, or technical question;
- organizing a note or project record;
- drafting or revising written material;
- handling documents and extracting relevant information;
- preparing updates for later review;
- maintaining separate Codex tasks across different projects; and
- checking returned work against the source information where it will be used.

Background automations are tracked separately from this direct use because they can run without requiring the same amount of active attention.

## Key Actions

1. Identify the immediate question, document, or task.
2. Provide the relevant source material and project context.
3. Use AI for the portion of the work where it is useful.
4. Review the result and decide whether more work is needed.
5. Move to another task or stop using AI when the current work no longer needs it.
6. Allow established automations to continue independently of direct working sessions.

## Important Features

- Direct AI use is variable rather than a fixed daily routine.
- Short interactions can address one bounded need without becoming a longer session.
- Longer sessions may combine several distinct tasks and project contexts.
- Background automations and active AI work are treated as different categories of use.
- The amount of use follows the work rather than a daily target.

## Constraints And Decisions

The durations in this record are approximate personal observations, not measurements from a complete activity tracker. They should not be read as a daily average or as a claim that longer use is better.

The work performed during a longer session may be distributed across several Codex tasks. It is not necessarily one continuous conversation or one uninterrupted block of attention.

Automation activity is excluded because an automated process can run without representing active working time. No productivity increase, time saving, or output multiplier is claimed.

## Deliverables

Depending on the day and the task, direct AI work may produce:

- research notes;
- organized project information;
- written drafts and revisions;
- document summaries or extracted action items;
- separate task outputs prepared for review; and
- updates to working records.

These are possible outputs across the workflow, not deliverables produced during every session.

## Outcome

The recorded pattern is a range of use rather than a fixed habit. Some workdays need only a brief interaction. Other workdays involve a longer series of research, drafting, document, and project tasks.

The observation also separates active use from background automation so the two are not treated as the same measure of AI involvement.

## Tools And Methods

- Codex for direct research, drafting, document, and project tasks;
- separate task threads when work belongs to different projects or contexts;
- source documents and project records for grounding the work;
- local automations for recurring background processes; and
- human review before generated work is used or added to a project record.

## Evidence And Limitations

This record is grounded primarily in Daniel's direct statement about the variation in his daily AI use. A prior private workflow record supports the use of several Codex tasks across different projects and the task categories used as examples.

The durations are approximate and have not been verified against a complete usage log. The record does not establish how often either pattern occurs, how long background automations run, or whether a longer session produces more useful work than a shorter one. It does not identify any private project, client, source document, or task content.
