# Using AI to Test and Repair My Internal Tools

## LinkedIn Summary

While developing internal tools to help me record and organize my notes, I designed an adversarial testing workflow for the AI.

I had it use the application, work through the workflows, and deliberately try to break things. The goal was to find bugs by interacting with the software and pushing beyond the normal way I would use it.

I also gave it instructions to fix the issues it found during testing and push those fixes to production. That made testing and repair part of the same workflow, rather than leaving me with a list of bugs to work through later.

I knew how I expected the tools to work. I wanted the AI to challenge those expectations and find where the actual behavior fell short.

## Overview

While developing internal software to help me record and organize notes, I designed an adversarial testing method using AI. I wanted it to interact with the application, exercise the workflows, and intentionally look for ways to break the software.

The testing instructions also covered what to do when an issue was found: fix it and push the correction to production.

## Role

I was developing the tools for my own use and defining how I expected them to behave. I designed the testing approach and authorized the AI to carry issues through to fixes and production updates.

## Scope Of Work

The work focused on internal note-taking tools and the workflows within those applications. The AI was directed to use the software in an adversarial manner, looking for behavior that exposed bugs in the implementation.

This included application use, investigation of problems encountered during testing, code changes to address them, and deployment of those corrections.

## Key Actions

- Develop internal tools for recording and organizing notes.
- Define an adversarial testing workflow for the AI.
- Have the AI interact with the application and exercise its workflows.
- Direct it to deliberately seek failures beyond ordinary use.
- Authorize fixes and production updates for issues found during testing.

## Important Features

The testing centered on using the application. A workflow can look reasonable in the code and still behave differently when someone works through it. I wanted the AI to explore that behavior and challenge the assumptions behind the implementation.

The repair instructions were part of the same process. When testing exposed something that needed fixing, the AI had direction to work on the correction and push it to production, instead of stopping at a report of the problem.

## Constraints And Decisions

These were internal tools I was developing around my own needs. That gave me a direct role in deciding what the software should do and how much responsibility to give the AI during testing and repair.

I deliberately asked for adversarial behavior. Following the expected workflow was only part of the exercise; the intent was to discover where the application stopped behaving as intended.

## Deliverables

An AI-directed adversarial testing and repair workflow for internal note-taking software, with instructions covering application use, bug investigation, corrections, and production deployment.

## Outcome

I extended the AI's role in development to include challenging the software through use and addressing the issues it encountered. Testing and repair were connected within the workflow I designed.

## Tools And Methods

AI-assisted software development, application workflow testing, adversarial testing, code repair, and production deployment instructions.

## Evidence And Limitations

This account describes my testing approach and the authority I gave the AI. It does not quantify bugs found or claim that the process identified every defect.
